# 마이링크(MyLink) 제품 요구사항 정의서 (PRD)

**버전**: v0.3

## 1. 프로젝트 개요

*   **프로젝트명**: 마이링크 (MyLink)
*   **목적**: 사용자가 자신이 운영하는 여러 소셜 미디어, 웹사이트, 블로그 등의 링크를 하나의 페이지에 모아 단일 URL로 쉽게 공유할 수 있도록 지원하는 링크 연결 서비스.
*   **대상 사용자**: 여러 외부 링크를 한 곳에서 공유 및 관리하고자 하는 유저 (크리에이터, 인플루언서, 개인 사업자 등).

## 2. 기술 스택 및 디자인 요구사항

*   **디자인 시스템**: **shadcn/ui** 사용.
*   **레이아웃 기준**: 모바일에 최적화하되 데스크톱 및 태블릿 환경에서는 뷰포트 크기에 맞게 가로로 늘어나는 **확장된 형태(Responsive)** 레이아웃 제공. (모바일 뷰 미리보기 화면 및 테마 변경 관련 기능은 일절 없음)
*   **인증 및 DB 인프라**: **Firebase** 사용.

## 3. 데이터베이스(Firebase) 모델링 핵심 요구사항

*   **유저 정보**: 사용자 계정 생성 및 저장 시 기본 `displayName` 외에도 화면에 보여질 실제 사용자의 이름을 나타내는 `username` 필드를 필수로 추가 포함하여 설계합니다. (※ 이미지 업로드 기능 없음)
*   **초기 데이터 세팅**: 회원가입 시 구글 이메일(Gmail) 아이디의 앞 부분(예: `abc@gmail.com`의 `abc`)을 추출하여 URL 슬러그(Slug)로 사용될 `displayName`의 초기값으로 자동 설정합니다.
*   **데이터 구조화**: 한 사용자가 등록하는 여러 개의 링크 데이터들은 해당 사용자 문서(Document)의 **서브 컬렉션(Subcollection)**으로 구조화하여 저장합니다.

### 📝 데이터베이스 스키마 구조
```typescript
// 1. 사용자(User) 문서 모델 - [Collection: users]
interface User {
  uid: string;            // 구글 Auth UID
  email: string;          // 구글 이메일
  displayName: string;    // 사용자 고유 URL 슬러그 (초기값: 이메일 '@' 앞부분)
  username: string;       // 화면에 표시될 실제 이름
  bio: string;            // 상세 소개글
  createdAt: Timestamp;   
}

// 2. 링크(Link) 서브 문서 모델 - [Subcollection: users/{uid}/links]
interface Link {
  id: string;             // 링크 고유 ID
  title: string;          // 링크 표시 이름
  url: string;            // 실제 연결될 URL 주소
  faviconUrl: string;     // 구글 파비콘 API를 통해 가져온 썸네일 URL
  clickCount: number;     // 링크 클릭 조회수 (향후 반영)
  order: number;          // 정렬 순서 (인라인 편집 시 순서 관리용)
  createdAt: Timestamp;   
}
```

## 4. 기능 요구사항

### 🔴 필수 기능

1.  **사용자 인증 (Firebase Auth)**
    *   오직 **구글 소셜 로그인(Google Auth)**을 통해서만 회원가입 및 서비스 로그인이 가능합니다.
2.  **프로필 및 링크 관리 대시보드**
    *   **프로필 설정 및 수정**: URL 슬러그(Slug)로 사용될 **닉네임(displayName)** 외에 페이지에 표시할 실제 이름인 **유저네임(username)**을 관리합니다. 유저네임, 닉네임, 상세 소개글은 모두 사용자가 직접 수정 가능하며, 페이지 이동 없이 **인라인 편집(Inline Editing)** 방식으로 그 자리에서 즉시 수정합니다.
    *   **링크 추가 및 인라인 수정**: 새로운 연결 링크(URL 주소, 링크명)를 추가하거나 기존 링크를 삭제할 수 있습니다. 이미 등록된 링크의 텍스트나 URL 수정 역시 **인라인 편집(Inline Editing)** 방식으로 처리됩니다.
    *   **파비콘(Favicon) 자동 연동**: 사용자가 링크를 등록하면, **구글 제공 파비콘 API**(`https://s2.googleusercontent.com/s2/favicons?domain=...`)를 활용하여 해당 URL 사이트의 파비콘 이미지를 가져오고 링크 버튼의 좌측 아이콘으로 표시합니다.
3.  **개인화된 유저 페이지 기능**
    *   서비스 가입 시 본인만의 고유 주소 체계인 `도메인.com/닉네임(displayName)` 구조의 URL이 자동 접속 경로로 확정됩니다.
    *   부여받은 URL 주소에 접속하면 사용자가 등록해 둔 프로필(유저네임, 소개) 정보와 링크 목록이 렌더링된 페이지가 출력됩니다.

### 🟡 향후 추가 기능

1.  **링크 클릭 조회수 제공**
    *   각 링크 버튼을 외부 방문자가 얼마나 눌렀는지 카운트하는 **개별 링크 클릭 조회수** 통계 기능을 추후 도입합니다. 

## 5. 사용자 경험 흐름 (User Flow)

1.  사용자가 서비스 메인 화면에 들어와 **구글 로그인**을 통해 회원가입을 완료합니다.
2.  가입 직후, 시스템은 구글 이메일의 아이디 부분(예: `abc@gmail.com` -> `abc`)을 추출해 **닉네임(displayName)**으로 1차 등록하며, 이를 향후 접속 주소(URL Slug)로 자동 활용합니다.
3.  대시보드 화면이 나타나면 자신의 **프로필(유저네임, 닉네임, 소개글)** 정보와 다른 사람들에게 알리고 싶은 **링크(URL, 링크명)**를 차례로 기입합니다. 정보 수정이 필요할 경우, 텍스트를 클릭하여 바로 인라인 편집을 수행합니다.
4.  부여받은 `도메인.com/닉네임(displayName)` 프로필 주소를 인스타그램 하단 등 필요한 곳에 배치하여 홍보합니다.
5.  그 주소를 통해 접속한 방문객들은 사용자의 링크 목록(구글 API를 통해 불러온 해당 사이트의 파비콘 포함)을 확인하고 각각의 페이지로 이동합니다.
